@@ job | Java · Temel | JDK, JRE ve JVM farkı nedir?
A: **JVM** (Java Virtual Machine) bytecode'u çalıştıran sanal makinedir. **JRE** = JVM + standart kütüphaneler (çalıştırmak için). **JDK** = JRE + derleyici (`javac`), debugger vb. (geliştirmek için).
Akış: `.java` → `javac` → `.class` (bytecode) → JVM → (JIT ile) makine kodu.
EX: “Write once, run anywhere”: Aynı .jar dosyası Windows sunucuda da Linux container'da da çalışır, çünkü her platformun kendi JVM'i var.
SAY: Der Compiler übersetzt Java-Code in Bytecode, und die JVM führt diesen Bytecode plattformunabhängig aus.

@@ job | Java · Temel | Primitive tipler vs Wrapper (int vs Integer)
A: Java'da 8 primitive tip var: `byte, short, int, long, float, double, char, boolean`. Değeri direkt tutar, `null` olamaz.
Wrapper sınıflar (`Integer`, `Double`…) nesnedir, `null` olabilir ve Collections'da kullanılır (`List<int>` yazamazsın, `List<Integer>` yazarsın). Otomatik dönüşüme **autoboxing/unboxing** denir.
**Tuzak:** `Integer` null iken unboxing → NullPointerException.
CODE:
Map<String, Integer> stock = new HashMap<>();
int n = stock.get("Schraube"); // key yoksa get() null döner -> NPE!
int ok = stock.getOrDefault("Schraube", 0); // güvenli
EX: Stok yönetiminde “bilgi yok” ile “stok 0” farklı şeyler: `Integer` null = veri yok, 0 = gerçekten stok bitti.

@@ job | Java · Temel | == ile equals() farkı
A: `==` primitive'lerde değeri, nesnelerde **referansı** (aynı nesne mi?) karşılaştırır. `equals()` nesnelerin **içeriğini** karşılaştırır (sınıf doğru override ettiyse).
String'leri her zaman `equals()` ile karşılaştır.
CODE:
String a = new String("IML");
String b = new String("IML");
a == b        // false (farklı nesneler)
a.equals(b)   // true  (aynı içerik)
"IML".equals(input) // input null olsa bile NPE atmaz
EX: Sipariş durumunu `status == "SHIPPED"` ile kontrol eden kod bazen çalışır bazen çalışmaz (String pool yüzünden) — klasik production bug'ı.
SAY: Mit == vergleiche ich Referenzen, mit equals() den Inhalt der Objekte.

@@ job | Java · Temel | equals() ve hashCode() sözleşmesi
A: Kural: iki nesne `equals()` ile eşitse `hashCode()` değerleri de **aynı olmak zorunda**. Tersi gerekmez (farklı nesneler aynı hash'e sahip olabilir = collision).
Birini override edip diğerini etmezsen `HashMap`/`HashSet` bozulur: nesneyi koyarsın ama geri bulamazsın.
CODE:
record Part(String id, String supplier) {} // record ikisini de otomatik yazar

@Override public boolean equals(Object o) {
  if (this == o) return true;
  if (!(o instanceof Part p)) return false;
  return id.equals(p.id);
}
@Override public int hashCode() { return Objects.hash(id); }
EX: Tedarikçi listesinde aynı parçayı iki kez görmemek için `HashSet<Part>` kullanıyorsun; hashCode yoksa duplikatlar sessizce girer.

@@ job | Java · Collections | Map nedir? (Arkadaşına sorulan soru!)
A: `Map`, **key → value** çiftleri tutan bir veri yapısıdır. Her key benzersizdir; aynı key'e tekrar `put` yaparsan eski değerin üstüne yazar. `Collection` arayüzünden türemez, ayrı bir arayüzdür.
Önemli metotlar: `put, get, getOrDefault, containsKey, remove, putIfAbsent, merge, entrySet, keySet, values`.
Implementasyonlar: `HashMap` (sırasız, O(1)), `LinkedHashMap` (ekleme sırası), `TreeMap` (sıralı, O(log n)).
CODE:
Map<String, Integer> demand = new HashMap<>();
demand.put("Berlin", 120);
demand.put("Dortmund", 80);
demand.merge("Dortmund", 20, Integer::sum); // 100
for (Map.Entry<String, Integer> e : demand.entrySet()) {
    System.out.println(e.getKey() + " -> " + e.getValue());
}
EX: Bedarfsmanagement: şehir → talep miktarı; ya da Lieferant-ID → Lieferant nesnesi. ID ile anında (O(1)) tedarikçiyi bulursun, listeyi baştan sona taramazsın.
SAY: Eine Map speichert Schlüssel-Wert-Paare; jeder Schlüssel ist eindeutig. Die HashMap bietet im Durchschnitt Zugriff in O(1).

@@ job | Java · Collections | HashMap içeride nasıl çalışır?
A: 1) Key'in `hashCode()` değeri alınır. 2) Bundan bir **bucket** (dizi indeksi) hesaplanır. 3) Değer o bucket'a konur.
İki key aynı bucket'a düşerse (**collision**) bucket içinde liste tutulur; Java 8'den beri bir bucket çok dolarsa (8+) **dengeli ağaca (red-black tree)** çevrilir.
Doluluk **load factor** (varsayılan 0.75) aşılınca dizi 2 katına çıkar ve elemanlar yeniden dağıtılır (**rehashing**).
`HashMap` thread-safe değildir, bir tane `null` key kabul eder.
EX: Kötü bir hashCode (ör. hep `return 1;`) yazarsan tüm elemanlar tek bucket'a düşer, HashMap yavaş bir yapıya dönüşür.
SAY: Bei einer Kollision landen mehrere Einträge im selben Bucket; seit Java 8 wird ein voller Bucket in einen Baum umgewandelt.

@@ job | Java · Collections | HashMap vs TreeMap vs LinkedHashMap vs ConcurrentHashMap
A:
- `HashMap`: sıra garantisi yok, ortalama O(1). Varsayılan seçim.
- `LinkedHashMap`: ekleme sırasını korur (LRU cache yapmak için de kullanılır).
- `TreeMap`: key'lere göre sıralı, O(log n), `firstKey()`, `headMap()` gibi aralık sorguları.
- `ConcurrentHashMap`: çok thread'li ortamlarda güvenli ve hızlı (eski `Hashtable` yerine).
EX: Tarihe göre sıralı teslimat planı → `TreeMap<LocalDate, List<Order>>`. Birden fazla thread'in güncellediği canlı stok sayacı → `ConcurrentHashMap`.

@@ job | Java · Collections | ArrayList vs LinkedList
A: `ArrayList` arkada dinamik bir dizi kullanır: indeksle erişim O(1), sona ekleme amortize O(1), ortadan silme O(n).
`LinkedList` çift yönlü bağlı listedir: indeksle erişim O(n), baştan/sondan ekleme-silme O(1).
Pratikte neredeyse hep **ArrayList** kullanılır (cache-dostu, hızlı). Kuyruk lazımsa `ArrayDeque` tercih edilir.
EX: Gelen sensör ölçümlerini listeleyip rapor çıkarmak → ArrayList. FIFO iş kuyruğu → ArrayDeque.
SAY: In der Praxis nutze ich meistens ArrayList, weil der Zugriff per Index in O(1) erfolgt.

@@ job | Java · Exceptions | NullPointerException olursa ne yaparsın? (Sorulan soru!)
A: NPE, `null` olan bir referans üzerinde metot/alan çağırınca oluşur. Cevabın 3 parçalı olsun:
- **1. Analiz:** Stack trace'e bak: hangi satır, hangi değişken null? (Java 14+ “helpful NPE” mesajı değişkeni direkt söyler.) Debugger ile değeri takip et.
- **2. Kök nedeni düzelt:** Değer neden null? Eksik veri mi, başlatılmamış alan mı, `get()` boş mu döndü? NPE'yi `catch` ile yutmak çözüm değildir.
- **3. Önle:** Girişte doğrula (`Objects.requireNonNull`), `Optional` döndür, null yerine boş koleksiyon döndür, `"sabit".equals(x)` yaz, unit test ekle.
CODE:
public Supplier find(String id) {
    Objects.requireNonNull(id, "id must not be null");
    return repo.findById(id)
        .orElseThrow(() -> new SupplierNotFoundException(id));
}
EX: Müşteriden gelen CSV'de “Lieferant” sütunu boşsa ve kod direkt `supplier.getName()` çağırıyorsa gece batch işi çöker. Doğru çözüm: import sırasında satırı doğrula, hatalı satırı logla, işleme devam et.
SAY: Ich schaue zuerst in den Stacktrace, finde heraus, warum der Wert null ist, und verhindere es dann durch Validierung oder Optional – nicht durch ein leeres catch.

@@ job | Java · Exceptions | Exception hiyerarşisi: checked vs unchecked
A: `Throwable` → `Error` (ör. OutOfMemoryError, normalde yakalanmaz) ve `Exception`.

- **Unchecked** (`RuntimeException` altı, ör. `NullPointerException`, `IllegalArgumentException`, `IndexOutOfBoundsException`): genelde programlama hatası, derleyici zorlamaz.
EX: Dosya okumak her zaman başarısız olabilir (dosya yok) → checked. Negatif sipariş miktarı göndermek çağıranın hatası → `IllegalArgumentException` (unchecked).
SAY: Checked Exceptions muss ich behandeln oder deklarieren, Unchecked Exceptions sind meistens Programmierfehler.

@@ job | Java · Exceptions | try-catch-finally ve try-with-resources

@@ job | Java · OOP | OOP'nin 4 temel prensibi
A:

EX: `Transport` arayüzü: `Truck`, `Ship`, `Train` farklı maliyet hesaplar. Rota planlayan kod sadece `transport.cost(distance)` çağırır, hangi araç olduğunu umursamaz.

@@ job | Java · OOP | Abstract class vs Interface
A: **Interface**: “ne yapabilir” sözleşmesi; bir sınıf birden çok interface implemente edebilir; Java 8'den beri `default` ve `static` metot içerebilir, instance alanı tutamaz.
**Abstract class**: ortak kod + durum paylaşan kısmi implementasyon; sadece bir sınıftan `extends` edilebilir; constructor'ı olabilir.
Kural: önce interface düşün; ortak state/kod gerekiyorsa abstract class.
EX: `RiskCalculator` interface'i (farklı risk modelleri), `AbstractImporter` abstract class'ı (CSV/Excel importer'ların ortak dosya açma + loglama kodu).

@@ job | Java · OOP | Overloading vs Overriding
A: **Overloading**: aynı sınıfta aynı isim, farklı parametreler (derleme zamanında seçilir). **Overriding**: alt sınıf üst sınıfın metodunu aynı imzayla yeniden yazar (çalışma zamanında seçilir = polymorphism). `@Override` anotasyonunu her zaman yaz.
CODE:
int add(int a, int b)           // overloading
double add(double a, double b)

class Ship extends Transport {
  @Override double cost(double km) { return km * 0.02; } // overriding
}

@@ job | Java · OOP | static ne demek?

Dikkat: değiştirilebilir static durum (global state) test etmeyi zorlaştırır, thread-safety sorunu yaratır.

@@ job | Java · Temel | Stack vs Heap, Garbage Collector
A: **Stack**: her thread'in metot çağrıları, lokal değişkenler, referanslar; hızlı, otomatik temizlenir. **Heap**: tüm nesneler (`new`); **Garbage Collector** artık referansı kalmayan nesneleri temizler.

@@ job | Java · Modern | Generics ve type erasure

@@ job | SQL | SELECT, JOIN türleri, GROUP BY
A: `INNER JOIN`: iki tabloda da eşleşenler. `LEFT JOIN`: soldakilerin hepsi + eşleşen sağdakiler (yoksa NULL). `RIGHT`, `FULL OUTER` daha nadir.
`WHERE` gruplamadan önce satırları, `HAVING` gruplamadan sonra grupları filtreler.
CODE:
SELECT s.name, COUNT(o.id) AS late_orders
FROM supplier s
LEFT JOIN orders o ON o.supplier_id = s.id AND o.delivered > o.due
GROUP BY s.name
HAVING COUNT(o.id) > 3
ORDER BY late_orders DESC;
SAY: WHERE filtert Zeilen vor der Gruppierung, HAVING filtert die Gruppen danach.

@@ job | SQL | Index, Primary/Foreign Key, ACID, SQL vs NoSQL
A: **Primary key**: satırın benzersiz kimliği. **Foreign key**: başka tabloya referans (bütünlük). **Index**: arama için (genelde B-tree); okumayı hızlandırır, yazmayı biraz yavaşlatır.

EX: “Stoktan düş + siparişi kaydet” tek transaction olmalı; biri başarısızsa ikisi de geri alınır (rollback).

@@ job | Kodlama Mülakatı | Big-O notasyonu
A: Algoritmanın girdi büyüdükçe nasıl yavaşladığını anlatır.
- O(1): HashMap get, dizi indeksi
- O(log n): binary search, TreeMap
- O(n): tek döngü
- O(n log n): iyi sıralama (`Collections.sort`)
- O(n²): iç içe döngü
Bellek (space) karmaşıklığını da söyle.
EX: 1 milyon sipariş: O(n²) ≈ 10¹² adım (saatler), O(n) ≈ 10⁶ adım (milisaniyeler). HashMap kullanmanın sebebi bu.

@@ job | Kodlama Mülakatı | Klasik: Two Sum (HashMap ile)
A: Bir dizide toplamı `target` olan iki elemanın indekslerini bul. Brute force iç içe döngü O(n²). Optimal: gezerken gördüklerini Map'te tut; her eleman için `target - x` daha önce görüldü mü bak → O(n).
CODE:
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>(); // değer -> indeks
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);
    }
    return new int[0];
}

@@ job | Kodlama Mülakatı | Klasik: Kelime/eleman frekansı saymak
A: Map sorusunun pratik hali. Her eleman için sayacı artır: `merge` veya `getOrDefault`.
CODE:
Map<String, Integer> countWords(String text) {
    Map<String, Integer> freq = new HashMap<>();
    if (text == null || text.isBlank()) return freq;
    for (String w : text.toLowerCase().split("\\s+")) {
        freq.merge(w, 1, Integer::sum);
    }
    return freq;
}
// Python: collections.Counter(text.lower().split())
EX: Hangi parça en çok iade ediliyor, hangi tedarikçi en çok gecikiyor — hepsi “frekans say” problemi.

@@ job | Kodlama Mülakatı | Klasik: Palindrom / String ters çevirme
A: İki işaretçi (two pointers): biri baştan, biri sondan, ortada buluşana kadar karşılaştır. O(n) zaman, O(1) bellek.
CODE:
boolean isPalindrome(String s) {
    if (s == null) return false;
    int l = 0, r = s.length() - 1;
    while (l < r) {
        if (s.charAt(l) != s.charAt(r)) return false;
        l++; r--;
    }
    return true;
}
String reverse(String s) { return new StringBuilder(s).reverse().toString(); }
