@@ job | Java · Temel | JDK, JRE ve JVM farkı nedir?
A: **JVM** (Java Virtual Machine) bytecode'u çalıştıran sanal makinedir. **JRE** = JVM + standart kütüphaneler (çalıştırmak için). **JDK** = JRE + derleyici (`javac`), debugger vb. (geliştirmek için).
Akış: `.java` → `javac` → `.class` (bytecode) → JVM → (JIT ile) makine kodu.
EX: “Write once, run anywhere”: Aynı .jar dosyası Windows sunucuda da Linux container'da da çalışır, çünkü her platformun kendi JVM'i var.
SAY: Der Compiler übersetzt Java-Code in Bytecode, und die JVM führt diesen Bytecode plattformunabhängig aus.

@@ job | Java · Temel | main metodu: public static void main(String[] args) ne demek?
A: Programın giriş noktası. Her kelimenin bir sebebi var:
- `public`: JVM dışarıdan çağırabilsin.
- `static`: henüz hiç nesne yok; JVM metodu sınıf üzerinden çağırır.
- `void`: bir şey döndürmez (hata koduyla çıkmak için `System.exit(1)`).
- `String[] args`: komut satırından gelen argümanlar.
Java 25'ten beri kısa `void main()` yazımı da var, ama mülakatta klasik hali açıklayabilmelisin.
CODE:
public class Importer {
    public static void main(String[] args) {
        String file = args.length > 0 ? args[0] : "orders.csv";
        System.out.println("Importing " + file);
    }
}
// Terminal: java Importer lieferungen.csv
EX: Gece çalışan import job'u `java -jar importer.jar lieferungen.csv` ile başlatılır; dosya adı `args[0]` olarak gelir.
SAY: Die main-Methode ist static, weil die JVM sie aufrufen muss, bevor ein Objekt existiert.

@@ job | Java · Temel | Primitive tipler vs Wrapper (int vs Integer)
A: Java'da 8 primitive tip var: `byte, short, int, long, float, double, char, boolean`. Değeri direkt tutar, `null` olamaz.
Wrapper sınıflar (`Integer`, `Double`…) nesnedir, `null` olabilir ve Collections'da kullanılır (`List<int>` yazamazsın, `List<Integer>` yazarsın). Otomatik dönüşüme **autoboxing/unboxing** denir.
**Tuzak:** `Integer` null iken unboxing → NullPointerException.
**Tuzak 2:** `Integer`'ları `==` ile karşılaştırma: -128..127 arası önbellekten gelir (`true`), dışında farklı nesneler olur (`false`). Hep `equals()` kullan.
CODE:
Map<String, Integer> stock = new HashMap<>();
int n = stock.get("Schraube"); // key yoksa get() null döner -> NPE!
int ok = stock.getOrDefault("Schraube", 0); // güvenli
EX: Stok yönetiminde “bilgi yok” ile “stok 0” farklı şeyler: `Integer` null = veri yok, 0 = gerçekten stok bitti.

@@ job | Java · Temel | == ile equals() farkı
A: `==` primitive'lerde değeri, nesnelerde **referansı** (aynı nesne mi?) karşılaştırır. `equals()` nesnelerin **içeriğini** karşılaştırır (sınıf doğru override ettiyse).
String'leri her zaman `equals()` ile karşılaştır.
CODE:
String a = new String("IML");
String b = new String("IML");
a == b        // false (farklı nesneler)
a.equals(b)   // true  (aynı içerik)
"IML".equals(input) // input null olsa bile NPE atmaz
EX: Sipariş durumunu `status == "SHIPPED"` ile kontrol eden kod bazen çalışır bazen çalışmaz (String pool yüzünden) — klasik production bug'ı.
SAY: Mit == vergleiche ich Referenzen, mit equals() den Inhalt der Objekte.

@@ job | Java · Temel | equals() ve hashCode() sözleşmesi
A: Kural: iki nesne `equals()` ile eşitse `hashCode()` değerleri de **aynı olmak zorunda**. Tersi gerekmez (farklı nesneler aynı hash'e sahip olabilir = collision).
Birini override edip diğerini etmezsen `HashMap`/`HashSet` bozulur: nesneyi koyarsın ama geri bulamazsın.
CODE:
record Part(String id, String supplier) {} // record ikisini de otomatik yazar

@Override public boolean equals(Object o) {
  if (this == o) return true;
  if (!(o instanceof Part p)) return false;
  return id.equals(p.id);
}
@Override public int hashCode() { return Objects.hash(id); }
EX: Tedarikçi listesinde aynı parçayı iki kez görmemek için `HashSet<Part>` kullanıyorsun; hashCode yoksa duplikatlar sessizce girer.

@@ job | Java · Temel | Integer bölme, overflow ve BigDecimal
A: `int / int` sonucu **tam sayıdır**, küsurat atılır: `7 / 2 == 3`. Ondalık lazımsa birini `double` yap: `7 / 2.0`. `%` kalanı verir (`n % 2 == 0` → çift).
`int` en fazla ~2,1 milyar; aşınca hata vermez, **negatife döner (overflow)**. Büyük sayılar için `long`.
Para için `double` değil `BigDecimal`: `0.1 + 0.2` double'da tam `0.3` etmez.
CODE:
int avg = 7 / 2;                  // 3
double ok = 7 / 2.0;              // 3.5
int big = Integer.MAX_VALUE + 1;  // -2147483648 (overflow)
long safe = 3_000_000_000L;
BigDecimal sum = new BigDecimal("0.10").add(new BigDecimal("0.20")); // 0.30
EX: Sipariş başına ortalama miktarı `total / count` ile hesaplarsan küsurat kaybolur; fatura tutarlarını `double` ile tutarsan kuruş farkları çıkar.
SAY: Für Geldbeträge verwende ich BigDecimal statt double, weil double Rundungsfehler hat.

@@ job | Java · Collections | Map nedir? (Arkadaşına sorulan soru!)
A: `Map`, **key → value** çiftleri tutan bir veri yapısıdır. Her key benzersizdir; aynı key'e tekrar `put` yaparsan eski değerin üstüne yazar. `Collection` arayüzünden türemez, ayrı bir arayüzdür.
Önemli metotlar: `put, get, getOrDefault, containsKey, remove, putIfAbsent, merge, entrySet, keySet, values`.
Implementasyonlar: `HashMap` (sırasız, O(1)), `LinkedHashMap` (ekleme sırası), `TreeMap` (sıralı, O(log n)).
CODE:
Map<String, Integer> demand = new HashMap<>();
demand.put("Berlin", 120);
demand.put("Dortmund", 80);
demand.merge("Dortmund", 20, Integer::sum); // 100
for (Map.Entry<String, Integer> e : demand.entrySet()) {
    System.out.println(e.getKey() + " -> " + e.getValue());
}
EX: Bedarfsmanagement: şehir → talep miktarı; ya da Lieferant-ID → Lieferant nesnesi. ID ile anında (O(1)) tedarikçiyi bulursun, listeyi baştan sona taramazsın.
SAY: Eine Map speichert Schlüssel-Wert-Paare; jeder Schlüssel ist eindeutig. Die HashMap bietet im Durchschnitt Zugriff in O(1).

@@ job | Java · Collections | HashMap içeride nasıl çalışır?
A: 1) Key'in `hashCode()` değeri alınır. 2) Bundan bir **bucket** (dizi indeksi) hesaplanır. 3) Değer o bucket'a konur.
İki key aynı bucket'a düşerse (**collision**) bucket içinde liste tutulur; Java 8'den beri bir bucket çok dolarsa (8+) **dengeli ağaca (red-black tree)** çevrilir.
Doluluk **load factor** (varsayılan 0.75) aşılınca dizi 2 katına çıkar ve elemanlar yeniden dağıtılır (**rehashing**).
`HashMap` thread-safe değildir, bir tane `null` key kabul eder.
EX: Kötü bir hashCode (ör. hep `return 1;`) yazarsan tüm elemanlar tek bucket'a düşer, HashMap yavaş bir yapıya dönüşür.
SAY: Bei einer Kollision landen mehrere Einträge im selben Bucket; seit Java 8 wird ein voller Bucket in einen Baum umgewandelt.

@@ job | Java · Collections | HashMap vs TreeMap vs LinkedHashMap vs ConcurrentHashMap
A:
- `HashMap`: sıra garantisi yok, ortalama O(1). Varsayılan seçim.
- `LinkedHashMap`: ekleme sırasını korur (LRU cache yapmak için de kullanılır).
- `TreeMap`: key'lere göre sıralı, O(log n), `firstKey()`, `headMap()` gibi aralık sorguları.
- `ConcurrentHashMap`: çok thread'li ortamlarda güvenli ve hızlı (eski `Hashtable` yerine).
EX: Tarihe göre sıralı teslimat planı → `TreeMap<LocalDate, List<Order>>`. Birden fazla thread'in güncellediği canlı stok sayacı → `ConcurrentHashMap`.

@@ job | Java · Collections | ArrayList vs LinkedList
A: `ArrayList` arkada dinamik bir dizi kullanır: indeksle erişim O(1), sona ekleme amortize O(1), ortadan silme O(n).
`LinkedList` çift yönlü bağlı listedir: indeksle erişim O(n), baştan/sondan ekleme-silme O(1).
Pratikte neredeyse hep **ArrayList** kullanılır (cache-dostu, hızlı). Kuyruk lazımsa `ArrayDeque` tercih edilir.
EX: Gelen sensör ölçümlerini listeleyip rapor çıkarmak → ArrayList. FIFO iş kuyruğu → ArrayDeque.
SAY: In der Praxis nutze ich meistens ArrayList, weil der Zugriff per Index in O(1) erfolgt.

@@ job | Java · Collections | List, Set, Queue – Collection hiyerarşisi
A: `Collection` arayüzünün altında:
- `List`: sıralı, duplikat olabilir (ArrayList)
- `Set`: duplikat yok (HashSet, LinkedHashSet, TreeSet)
- `Queue/Deque`: kuyruk/yığın (ArrayDeque, PriorityQueue)
`Map` bu ağacın içinde değildir. **Collection** (arayüz) ile **Collections** (yardımcı sınıf: `sort`, `unmodifiableList`…) farklıdır.
EX: Bir siparişteki benzersiz tedarikçiler → `Set`. Öncelikli acil siparişler → `PriorityQueue`.

@@ job | Java · Collections | HashSet içeride nasıl çalışır?
A: `HashSet` arkada bir `HashMap` kullanır: eklediğin eleman **key** olur, value olarak sabit bir yer tutucu nesne konur. Bu yüzden `add`, `contains`, `remove` ortalama O(1)'dir ve duplikat kontrolü `hashCode()` + `equals()` ile yapılır.
`add()` eleman zaten varsa `false` döner. Sıra garantisi yok: ekleme sırası için `LinkedHashSet`, sıralı için `TreeSet` (O(log n)).
**Tuzak:** Set'e koyduktan sonra hashCode'u etkileyen alanı değiştirirsen eleman “kaybolur”.
CODE:
Set<String> seen = new HashSet<>();
for (String id : shipmentIds) {
    if (!seen.add(id)) {
        System.out.println("Duplikat: " + id);
    }
}
EX: EDI ile gelen sevkiyat bildirimlerinde aynı ID'nin iki kez işlenmesini tek satırlık `seen.add()` kontrolüyle engellersin.
SAY: Ein HashSet basiert intern auf einer HashMap; die Elemente sind die Schlüssel, deshalb gibt es keine Duplikate.

@@ job | Java · Collections | Comparable vs Comparator
A: `Comparable<T>`: sınıfın **doğal sıralaması**, sınıfın içinde `compareTo()` ile tanımlanır (tek bir sıralama).
`Comparator<T>`: sınıfın **dışında** tanımlanır; istediğin kadar farklı sıralama yazabilirsin.
Dönüş değeri: negatif = a önce, 0 = eşit, pozitif = b önce. `a - b` yazma (overflow riski), `Integer.compare(a, b)` kullan.
CODE:
record Order(String id, int priority, LocalDate due) implements Comparable<Order> {
    public int compareTo(Order o) { return id.compareTo(o.id); }
}
Collections.sort(orders);                      // doğal sıra: id
orders.sort(Comparator.comparing(Order::due)   // önce tarih,
    .thenComparing(Order::priority, Comparator.reverseOrder())); // sonra öncelik (büyük önce)
EX: Depo sevkiyat listesi: önce teslim tarihi, aynı gün olanlar önceliğe göre. Aynı `Order` sınıfı rapor ekranında başka bir `Comparator` ile tedarikçiye göre sıralanır.
SAY: Comparable definiert die natürliche Ordnung in der Klasse selbst; mit einem Comparator kann ich von außen beliebig viele Sortierungen definieren.

@@ job | Java · Collections | Array vs ArrayList
A: **Array** (`int[]`): boyutu sabit, primitive tutabilir, `length` alanı var. **ArrayList**: boyutu otomatik büyür, sadece nesne tutar (`Integer`), `size()` ve hazır metotlar (`add`, `remove`, `contains`).
Tuzaklar:
- `Arrays.asList(...)` sabit boyutludur: `set` çalışır, `add` → `UnsupportedOperationException`.
- `List.of(...)` tamamen değiştirilemez ve `null` kabul etmez.
- Değiştirilebilir kopya: `new ArrayList<>(List.of(...))`.
CODE:
int[] qty = new int[3];           // {0, 0, 0}, qty.length == 3
List<Integer> list = new ArrayList<>();
list.add(5);                      // list.size() == 1
List<String> fixed = Arrays.asList("A", "B");
fixed.set(0, "X");                // OK
fixed.add("C");                   // UnsupportedOperationException
EX: Haftanın 7 günü için talep tahmini → `double[7]`. Gün içinde gelen, sayısı belli olmayan siparişler → `ArrayList<Order>`.
SAY: Ein Array hat eine feste Größe, eine ArrayList wächst dynamisch und bietet viele fertige Methoden.

@@ job | Java · Collections | ConcurrentModificationException ve Iterator
A: Bir listeyi `for-each` ile gezerken aynı listeden `remove`/`add` yaparsan genellikle `ConcurrentModificationException` alırsın — tek thread'de bile! For-each arkada bir `Iterator` kullanır; liste beklenmedik şekilde değişince hemen hata verir (**fail-fast**).
Doğru yollar: `removeIf()` ya da `Iterator.remove()`.
CODE:
for (Order o : orders) {
    if (o.isCancelled()) orders.remove(o);  // HATA
}

orders.removeIf(Order::isCancelled);         // doğru ve kısa

Iterator<Order> it = orders.iterator();
while (it.hasNext()) {
    if (it.next().isCancelled()) it.remove(); // doğru
}
EX: İptal edilen siparişleri gece batch'inde listeden temizlerken yapılan klasik hata; code review'da hemen göze batar.
SAY: Wenn ich eine Liste in einer for-each-Schleife verändere, bekomme ich eine ConcurrentModificationException; deshalb nutze ich removeIf oder den Iterator.

@@ job | Java · Collections | PriorityQueue ve ArrayDeque (Stack yerine ne?)
A: **`ArrayDeque`**: iki uçlu kuyruk; hem **queue (FIFO)** hem **stack (LIFO)** olarak kullanılır. Eski `Stack` sınıfı yerine bunu kullan (`Stack` eski ve gereksiz yere senkronize).
**`PriorityQueue`**: her zaman en küçük (ya da Comparator'a göre en öncelikli) elemanı verir. Arkada **heap** var: `offer`/`poll` O(log n), `peek` O(1).
**Tuzak:** PriorityQueue'yu for-each ile gezersen elemanlar sıralı gelmez; sıralı almak için `poll()`.
CODE:
Deque<String> stack = new ArrayDeque<>();
stack.push("a"); stack.pop();        // LIFO
Queue<String> queue = new ArrayDeque<>();
queue.offer("a"); queue.poll();      // FIFO
PriorityQueue<Order> urgent =
    new PriorityQueue<>(Comparator.comparing(Order::due));
Order next = urgent.poll();          // en erken teslim tarihli
EX: Depoda “en acil sipariş önce toplanır” → `PriorityQueue`. Valid Parentheses gibi kodlama soruları → `ArrayDeque` ile stack.
SAY: Für Stack und Queue nehme ich ArrayDeque; eine PriorityQueue liefert immer das Element mit der höchsten Priorität.

@@ job | Java · Exceptions | NullPointerException olursa ne yaparsın? (Sorulan soru!)
A: NPE, `null` olan bir referans üzerinde metot/alan çağırınca oluşur. Cevabın 3 parçalı olsun:
- **1. Analiz:** Stack trace'e bak: hangi satır, hangi değişken null? (Java 14+ “helpful NPE” mesajı değişkeni direkt söyler.) Debugger ile değeri takip et.
- **2. Kök nedeni düzelt:** Değer neden null? Eksik veri mi, başlatılmamış alan mı, `get()` boş mu döndü? NPE'yi `catch` ile yutmak çözüm değildir.
- **3. Önle:** Girişte doğrula (`Objects.requireNonNull`), `Optional` döndür, null yerine boş koleksiyon döndür, `"sabit".equals(x)` yaz, unit test ekle.
CODE:
public Supplier find(String id) {
    Objects.requireNonNull(id, "id must not be null");
    return repo.findById(id)
        .orElseThrow(() -> new SupplierNotFoundException(id));
}
EX: Müşteriden gelen CSV'de “Lieferant” sütunu boşsa ve kod direkt `supplier.getName()` çağırıyorsa gece batch işi çöker. Doğru çözüm: import sırasında satırı doğrula, hatalı satırı logla, işleme devam et.
SAY: Ich schaue zuerst in den Stacktrace, finde heraus, warum der Wert null ist, und verhindere es dann durch Validierung oder Optional – nicht durch ein leeres catch.

@@ job | Java · Exceptions | Exception hiyerarşisi: checked vs unchecked
A: `Throwable` → `Error` (ör. OutOfMemoryError, normalde yakalanmaz) ve `Exception`.
- **Checked** (`Exception` altı, ör. `IOException`, `SQLException`): derleyici zorlar → ya `try/catch` ya `throws`.
- **Unchecked** (`RuntimeException` altı, ör. `NullPointerException`, `IllegalArgumentException`, `IndexOutOfBoundsException`): genelde programlama hatası, derleyici zorlamaz.
EX: Dosya okumak her zaman başarısız olabilir (dosya yok) → checked. Negatif sipariş miktarı göndermek çağıranın hatası → `IllegalArgumentException` (unchecked).
SAY: Checked Exceptions muss ich behandeln oder deklarieren, Unchecked Exceptions sind meistens Programmierfehler.

@@ job | Java · Exceptions | try-catch-finally ve try-with-resources
A: `finally` bloğu exception olsa da olmasa da çalışır. Modern yol: **try-with-resources** — `AutoCloseable` olan kaynaklar otomatik kapanır.
Kurallar: spesifik exception'ı yakala (`catch (Exception e)` değil), boş catch yazma, logla veya anlamlı bir exception'a sar.
CODE:
try (BufferedReader br = Files.newBufferedReader(path)) {
    return br.lines().toList();
} catch (IOException e) {
    log.error("Datei konnte nicht gelesen werden: {}", path, e);
    throw new ImportException("Import failed", e);
}
EX: DB bağlantısını kapatmayı unutmak → connection pool tükenir, uygulama birkaç saat sonra donar. try-with-resources bunu engeller.

@@ job | Java · Exceptions | throw vs throws, custom exception
A: `throw` bir exception **fırlatır** (metot içinde). `throws` metot imzasında hangi checked exception'ların fırlatılabileceğini **bildirir**.
Domain'e özel exception yazmak kodu okunur yapar.
CODE:
public class SupplierNotFoundException extends RuntimeException {
    public SupplierNotFoundException(String id) {
        super("Supplier not found: " + id);
    }
}
void load(Path p) throws IOException { ... }
EX: REST API'de `SupplierNotFoundException` → HTTP 404'e çevrilir (Spring'de `@ExceptionHandler` ile).

@@ job | Java · Exceptions | final, finally, finalize farkı
A: `final`: değişken tekrar atanamaz / metot override edilemez / sınıftan türetilemez. `finally`: try bloğundan sonra her zaman çalışan blok. `finalize()`: GC öncesi çağrılan eski metot — **deprecated**, kullanma.
Dikkat: `final` referans ≠ değişmez nesne. `final List<Order> l` başka listeye atanamaz ama `l.add(...)` çalışır. Lambda içinde kullanılan lokal değişkenler de **effectively final** olmalı (atandıktan sonra değişmemeli).
EX: `final` alanlar immutable nesne yazmanın temelidir: `private final List<Order> orders;`

@@ job | Java · OOP | OOP'nin 4 temel prensibi
A:
- **Encapsulation (Kapsülleme):** veri `private`, erişim metotlarla; nesne kendi durumunu korur.
- **Inheritance (Kalıtım):** `extends` ile ortak davranışı üst sınıftan alma.
- **Polymorphism (Çok biçimlilik):** aynı arayüz, farklı davranış (`Transport t = new Truck(); t.cost(km);`).
- **Abstraction (Soyutlama):** detayı gizle, sadece ne yaptığını göster (interface/abstract class).
EX: `Transport` arayüzü: `Truck`, `Ship`, `Train` farklı maliyet hesaplar. Rota planlayan kod sadece `transport.cost(distance)` çağırır, hangi araç olduğunu umursamaz.
SAY: Polymorphie bedeutet, dass ich über ein gemeinsames Interface unterschiedliche Implementierungen aufrufen kann.

@@ job | Java · OOP | Abstract class vs Interface
A: **Interface**: “ne yapabilir” sözleşmesi; bir sınıf birden çok interface implemente edebilir; Java 8'den beri `default` ve `static` metot içerebilir, instance alanı tutamaz.
**Abstract class**: ortak kod + durum paylaşan kısmi implementasyon; sadece bir sınıftan `extends` edilebilir; constructor'ı olabilir.
Kural: önce interface düşün; ortak state/kod gerekiyorsa abstract class.

@@ job | Java · OOP | Overloading vs Overriding

@@ job | Java · OOP | Immutable class nasıl yazılır?

@@ job | Java · Temel | Shallow copy vs deep copy
A: **Shallow copy** sadece dış nesneyi kopyalar; içindeki nesneler hâlâ **aynı referans**. **Deep copy** iç nesneleri de kopyalar.
`new ArrayList<>(list)`, `List.copyOf()`, `clone()` → shallow: liste yeni, elemanlar aynı nesneler. Elemanlar immutable ise (String, record) shallow copy yeterlidir.
CODE:
List<StringBuilder> a = new ArrayList<>();
a.add(new StringBuilder("A"));
List<StringBuilder> b = new ArrayList<>(a); // shallow copy
b.add(new StringBuilder("B")); // a etkilenmez (liste ayrı)
b.get(0).append("!");          // a.get(0) da "A!" olur (eleman aynı)
EX: “What-if” analizi için stok planını kopyalayıp değiştiriyorsun; shallow copy alırsan gerçek plan da değişir. Senaryolar için deep copy ya da immutable nesneler gerekir.
SAY: Bei einer flachen Kopie teilen sich Original und Kopie die inneren Objekte, bei einer tiefen Kopie nicht.

@@ job | Kodlama Mülakatı | Canlı kodlamada izlenecek 6 adım

@@ job | Kodlama Mülakatı | Big-O notasyonu
A: Algoritmanın girdi büyüdükçe nasıl yavaşladığını anlatır.
- O(1): HashMap get, dizi indeksi
- O(log n): binary search, TreeMap
- O(n): tek döngü
- O(n log n): iyi sıralama (`Collections.sort`)
- O(n²): iç içe döngü
Bellek (space) karmaşıklığını da söyle.
EX: 1 milyon sipariş: O(n²) ≈ 10¹² adım (saatler), O(n) ≈ 10⁶ adım (milisaniyeler). HashMap kullanmanın sebebi bu.

@@ job | Kodlama Mülakatı | Klasik: Two Sum (HashMap ile)
A: Bir dizide toplamı `target` olan iki elemanın indekslerini bul. Brute force iç içe döngü O(n²). Optimal: gezerken gördüklerini Map'te tut; her eleman için `target - x` daha önce görüldü mü bak → O(n).
CODE:
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>(); // değer -> indeks
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);
    }
    return new int[0];
}

@@ job | Kodlama Mülakatı | Klasik: Kelime/eleman frekansı saymak
A: Map sorusunun pratik hali. Her eleman için sayacı artır: `merge` veya `getOrDefault`.
CODE:
Map<String, Integer> countWords(String text) {
    Map<String, Integer> freq = new HashMap<>();
    if (text == null || text.isBlank()) return freq;
    for (String w : text.toLowerCase().split("\\s+")) {
        freq.merge(w, 1, Integer::sum);
    }
    return freq;
}
// Python: collections.Counter(text.lower().split())
EX: Hangi parça en çok iade ediliyor, hangi tedarikçi en çok gecikiyor — hepsi “frekans say” problemi.

@@ job | Kodlama Mülakatı | Klasik: Palindrom / String ters çevirme
A: İki işaretçi (two pointers): biri baştan, biri sondan, ortada buluşana kadar karşılaştır. O(n) zaman, O(1) bellek.
CODE:
boolean isPalindrome(String s) {
    if (s == null) return false;
    int l = 0, r = s.length() - 1;
    while (l < r) {
        if (s.charAt(l) != s.charAt(r)) return false;
        l++; r--;
    }
    return true;
}
String reverse(String s) { return new StringBuilder(s).reverse().toString(); }

@@ job | Kodlama Mülakatı | Klasik: FizzBuzz ve duplikat bulma
A: FizzBuzz basit ama mülakatçı modulo, if sırası ve temiz kodu görür. Duplikat bulma: `Set.add()` false dönerse eleman zaten vardır.
CODE:
for (int i = 1; i <= 100; i++) {
    if (i % 15 == 0) System.out.println("FizzBuzz");
    else if (i % 3 == 0) System.out.println("Fizz");
    else if (i % 5 == 0) System.out.println("Buzz");
    else System.out.println(i);
}

boolean hasDuplicate(int[] a) {
    Set<Integer> seen = new HashSet<>();
    for (int x : a) if (!seen.add(x)) return true;
    return false;
}
